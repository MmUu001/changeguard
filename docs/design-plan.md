# ChangeGuard「哨兵值守台」界面设计蓝图 v2

> 定位一句话：别的扫描工具给你看"报表"，ChangeGuard 给你的是一间**声呐室**——
> 你不是在看仪表盘，你是坐在值守台前，盯着一片持续被扫描的海域。
> 每一次 API 变更，都是一次被截获的"信号"。

## 0. 与上一版的关系

v1（已上线，commit c39acf7）确立了磷光绿终端 token：墨绿黑底 `#0b100e`、
磷光绿 `#4be3a0`、锐利 4px 直角、扫描网格、等宽读数。
v2 不推翻它，而是把"颜色像终端"升级为**"结构像仪器"**——
改变的是布局骨架、信息形态和动效语言，token 只做增量扩展。

## 1. 概念主张：SONAR ROOM（声呐值守室）

| 隐喻 | 对应产品事实 |
|---|---|
| 雷达/声呐 | 确定性扫描引擎持续巡逻（Tree-sitter × OpenAPI diff × 版本约束） |
| 信号截获 | 一条 finding = 一次截获记录，带时间戳与编号 |
| 电传简报 | HTML 报告 = 发给指挥官的 dispatch 电文 |
| 仪表 annunciator | 配额/渠道状态 = 机舱顶板告警灯条 |
| 门禁终端 | 登录 = 值守台准入认证 |

差异化记忆点：**市面上所有竞品都是"卡片网格 + 图表"，ChangeGuard 是唯一一个没有卡片的控制台。**

## 2. 设计原则（三条铁律）

1. **没有卡片网格。** 信息要么是"截获记录"（横向条目），要么是"仪表读数"（等宽数字），要么是"雷达"（图形）。
2. **一切皆电文。** 每条信息都有：编号、UTC 时间戳、来源标签。编号格式 `SIG-0042`。
3. **仪器感优先于装饰。** 动效只允许三种：雷达扫描、字条电传滚动、状态灯呼吸。其余一律静止。

字体：不引入外部字体（报告页必须单文件离线可用，零请求是硬约束）。

中文回退保持苹方/雅黑。可选增强（仅手册页，本地资源）：将一款开源等宽字体
（如 IBM Plex Mono）以 base64 woff2 内联，单独评估体积后再做。

## 4. 布局骨架

### 4.1 控制台（/）— 告别对称双栏

```
┌──────────────────────────────────────────────────────────────┐
│ ▮▮▮ SONAR ▸ CHANGEGUARD      [控制台][设置][手册][套餐] FREE  │ ← 页头+顶条
├──────────────────────────────────────────────────────────────┤
│ ◄ SIG-0017 扫描完成 sample-repo · HIGH 2 · 14:32:07 ◄ SIG-0…  │ ← 信号电传带(ticker)
├───────────────┬──────────────────────────────────────────────┤
│ 仪 表 柱(240px)│  主 海 域                                     │
│ ┌───────────┐ │ ┌──────────────────────────────────────────┐ │
│ │ 雷达盘     │ │ │ 截获记录 INTERCEPT LOG                    │ │
│ │ (SVG 扫描) │ │ │ SIG-0042 ▮HIGH  openai  v1→v2  4 calls   │ │
│ │ 仓库=回波点 │ │ │ SIG-0041 ▮MED   stripe  2024-…  1 call   │ │
│ └───────────┘ │ │ SIG-0040 ▯LOW   aws-sdk …               │ │
│ │ 配额表盘   │ │ │ …（hover 展开证据：AST/契约/diff）        │ │
│ │ 扫描 32/60 │ │ └──────────────────────────────────────────┘ │
│ │ 渠道灯条   │ │  [触发扫描输入条：横贯底部，像指令行]           │
│ │ ●SLACK ●IM│ │  $ scan D:\projects\my-api ▍                 │
│ └───────────┘ │                                              │
└───────────────┴──────────────────────────────────────────────┘
```

- **仪表柱**：固定窄列，纵向堆叠雷达盘、两个"表盘式"配额读数（圆弧 SVG，非进度条）、
  通知渠道 annunciator 灯条（绿=通/灭=未配/琥珀=异常）。移动端仪表柱折叠为页头下方横条。
- **信号电传带**：页头下 32px 高的横向滚动条，内容来自 `/api/audit` 最近事件，
  CSS marquee（`@keyframes` 位移），`prefers-reduced-motion` 时静止只显示最新一条。
- **截获记录**：扫描历史的表格彻底废弃。每条记录一行：编号 + 严重度色块 + 仓库名 +
  时间戳，hover/点击展开抽屉显示当时的风险计数与操作（报告/Issue/PR/删除）。
- **指令行输入条**：底部横贯的"命令行"式扫描触发输入，等宽字体 + 闪烁块状光标
  （CSS `steps()` 动画），按下 Enter 即触发扫描——这是全页唯一的拟物彩蛋。

### 4.2 雷达盘（核心创意件，零依赖）

- 实现：内联 SVG。外圈刻度环（CSS `stroke-dasharray`）、同心距环、
  一个 `<g>` 扫描扇形（CSS `rotate` 无限动画，60s/圈，透明渐变余辉）。
- 回波点 = 每个已登记仓库：距圆心的半径映射"最近一次高风险数"（0 高风险贴心，越多越外），
  回波颜色 = 最高严重度。扫描动画扫过回波点时 `stroke-width` 脉冲一次（纯 CSS，无 JS）。
- 数据来自现有 `/api/scans`，**不改任何后端契约**。

### 4.3 报告页（/reports/:id.html）— 「电传简报 DISPATCH」

```
┌──────────────────────────────────────────────┐
│ DISPATCH ▸ 影响简报          [火漆章: HIGH 2] │ ← 头部：等宽+右侧Severity图章
│ 2026-11-10T14:32Z · sample-repo · 模式 online │
├──────────────────────────────────────────────┤
│ ▓▓▓ 风险标尺 ▓▓▓░░░░░░  2H 3M 1L (共6)        │ ← 数字读数条，非卡片
├──────────────────────────────────────────────┤
│ SIG-0042 ─ 14:32:07Z ─────────────── ▮HIGH   │
│ openai 1.2.3 → 2.0.0 · chat.completions.create│
│ ┌ diff 区（保持现状，等宽深底）────────────┐  │
│ └ 修复步骤 1. 2. 3.（保持现状）───────────┘  │
│   [AI 生成，仅供参考] ← badge 保持绿色系       │
│ …                                            │
├──────────────────────────────────────────────┤
│ |||| ||| ||||| ||| （伪条形码 footer）        │ ← 判定指纹：按报告JSON哈希生成
│ 影响判定全部来自确定性规则 · LLM 仅解释        │
└──────────────────────────────────────────────┘
```

- **火漆章**：右上角旋转 -6° 的双线描边图章（高/中/低 颜色），`letter-spacing` 大写。
- **伪条形码**：用报告 JSON 哈希按位生成 1px 竖线序列——同一份报告永远得到同一个"指纹条码"，
  这是确定性引擎的视觉宣言（服务端生成，零 JS）。
- 过滤工具条从"胶囊按钮"改为"电传切换档位"（`[ALL] [HIGH] [AUTO-FIX]` 方括号样式）。

### 4.4 登录页 — 门禁终端

- 卡片升级为"准入终端"：顶部一行 `CHANGEGUARD ACCESS TERMINAL v0.2`，
  逐字打出（CSS `steps()` 逐帧），口令输入框下方常驻块状光标待命行 `> ▍`。
- 错误信息 = 终端错误行：`ACCESS DENIED — 口令错误`（红色，等宽，不弹窗）。
- 连续失败计数字样 `ATTEMPTS: 2`（已有 rate limit 逻辑，仅展示层）。

### 4.5 设置/文档中心/套餐页 — 同语言降密度

- 设置页各面板改为"仪表分区"：面板标题加编号（`SEC-01 租户` `SEC-02 扫描参数`），
  左侧 2px 色条标示区块状态。
- 文档中心 mcard 改为"档案抽屉"样式：左侧打孔条（CSS 渐变圆点列）。

## 5. 动效预算（全部 CSS，零 JS 动画库）

| 动效 | 位置 | 参数 |
|---|---|---|
| 雷达扫描旋转 | 雷达盘 | 60s linear infinite，`prefers-reduced-motion` 时静止 |
| 电传滚动 | 信号带 | 内容宽 / 30px per s，hover 暂停 |
| 块状光标闪烁 | 指令行/登录 | 1s steps(2) |
| 截获记录入场 | 列表首次加载 | stagger 40ms fade+slide，仅首屏一次 |
| 状态灯呼吸 | annunciator | 2s ease-in-out，仅异常态 |

## 6. 无障碍与性能红线

- 对比度：所有新绿/琥珀前景色继续满足 WCAG AA（v1 已验证基线）。
- 雷达 SVG 全部 `aria-hidden`，配额用 `<meter>`/文本冗余表达；ticker 提供 `role="log"` 替代文本。
- `prefers-reduced-motion` 一票否决所有动画（雷达静止为"满刻度盘"）。
- 报告页保持单文件零请求；控制台新增结构均内联，不新增构建步骤。

## 8. 设计语言演进记录（2026-11-13 补记）

> 本节修正本文档与代码现实之间的漂移。历史蓝图保留不删，但以现状为准。

### 8.1 Token 从绿 v1 → 紫 v2（已发生，本文档 §3 未更新）

- v1 磷光绿（`#0b100e` 底 / `#4be3a0` acc）仅存在于历史蓝图与 React 展示站
  （`changeguard-artifact/`，仓库外）。
- 服务端全部渲染页（dashboard / pricing / auth 登录页）现行 token 为**紫色
  Sonar**：`--bg:#0d0a14` / `--acc:#a78bfa` / `--acc-2:#7c3aed`，三处
  `:root` 与 `[data-theme="sonar-light"]` 已逐字节同源（2026-11-13 对照审计）。
- 套餐页蓝图的「铁律一：没有卡片网格」实际早已满足——`.tiers` 是横向条目
  列表（flex 行 + 底边框 + 当前档左侧 3px 色条），非卡片网格；`SEC-UP ▸`
  分区编号、`STANDING BY` 电传标签、等宽大写 panel-label 均已落地。
- **P5「套餐页统一」判定为已完成**。虚线 acc 边框 panel（`SEC-UP` 配置提示
  框）为有意的语义区分，保留，不视为失统。

### 8.2 等宽字体栈已统一（2026-11-13）

- 蓝图栈 `ui-monospace, "Cascadia Code", Consolas, monospace` 已在
  dashboard.ts（18 处）/ pricing.ts（19 处）/ auth.ts（5 处）全量落地，
  共替换 32 处简栈。
- **内联等宽字体（IBM Plex Mono woff2 base64）评估结论：不做。** 理由：
  ① 系统等宽栈（Win Cascadia / macOS app 内 Consolas→Menlo 回退）已满足
  「仪器感」需求，视觉增益边际小；② 单字重 woff2 约 50–100KB，base64 后
  +33%，与「报告页单文件零请求」的体积红线冲突；③ 仅为手册页引入会分裂
  两条字体策略。若未来做对外品牌站再评估。

### 8.3 给后续设计的教训

- 本文档是**蓝图**不是**现状快照**：P2 之后代码先于文档演进了两轮
  （绿→紫、套餐页统一），文档没跟。以代码审计为准，改动前先 grep 现行 token。
- React 展示站（`changeguard-artifact/`）使用绿色 v1 token，是刻意的
  门面差异（仓库外、不入主仓），不纳入统一范围。
